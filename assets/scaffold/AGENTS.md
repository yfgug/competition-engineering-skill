## 3. 工作树边界

- 开始新实验时记录 `base_commit` 和初始 `git status --short`
- 来源不明且与目标文件重叠的改动需要先确认
- 无关改动保留并绕开；本次工作产生的已知脏文件允许继续
- 非 Git 项目使用文件哈希快照，或经用户同意后初始化 Git

## 4. 实验纪律

- 因果/性能实验优先单变量；修复、集成和基础设施工作保持必要原子性
- 每条可量化路线先定义方向、硬约束、噪声方法和门槛
- `invalid` 先修评测条件；`inconclusive` 补证据；只有有效的 `fail` 才关闭路线
- 组合候选重新走完整验证，不能直接叠加成员收益
- 开新路线前查 `notes/_closed_routes.md`
- 本地评测写 `notes/_evaluations.md`；官方提交写 `notes/_submissions.md`
- 原始结果进入 `results/`，笔记保存路径、哈希和摘要
