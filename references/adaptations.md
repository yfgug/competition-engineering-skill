# 赛种裁剪表

所有赛种都保留三件事：可核验证据、明确权限边界、可恢复基线。笔记粒度、评测层级和门槛形式按风险与成本调整，不把性能优化赛的流程原样套到所有比赛。

| 赛种 | 主要评测设计 | 常见硬约束 | 推荐决策方式 |
|---|---|---|---|
| 算法/数据 | 固定切分、交叉验证、多随机种子、线下线上一致性 | 数据泄漏、提交配额、推理资源 | 主指标方向 + CV 方差 + 线上一致性 |
| 系统/性能 | A-B-A、交错运行、预热与缓存控制、尾延迟 | 正确性、超时、内存、功耗 | 配对差值 + 最小实际收益 + 约束全过 |
| 应用/黑客松 | 冒烟、关键路径、演示复现、降级方案 | 截止时间、功能完整、演示稳定 | 功能冻结门槛 + 连续演示成功 |
| 安全/CTF | 独立复现、证据链、已拿分清单 | 赛规、授权边界、凭证安全 | flag/复现成功；失败路线保留触发条件 |
| 机器人/嵌入式 | 仿真 + 实机、连续运行、最差情况、参数快照 | 安全、实时性、电量、硬件版本 | 连续成功次数 + 最差值 + 回滚能力 |
| 科研复现/论文 | 固定 benchmark、环境锁定、统计检验、claim-evidence | 论文协议、数据许可、伦理、引用与可复现性 | 误差容限 + 不确定性 + 图表/claim 可追踪 |

## 裁剪问题

1. 正式评测是什么，能否本地复现？
2. 指标是最大化、最小化还是多目标？
3. 哪些约束失败会使高分也不可接受？
4. 噪声来自随机性、硬件、数据切分还是官方评测？
5. 一次错误决策会损失多少算力、提交额度或时间？
6. 什么对象是可恢复基线：commit、模型权重、固件、参数快照还是已拿 flag？

## 短周期与低风险项目

周期短于一周或只有少量实验时，可以显著降档：

- `00_先看这里.md` 与实验记录可合并。
- 验证只保留 L0 和一次代表性评测。
- 关闭路线表可用笔记中的一节替代。
- 不创建不会被使用的目录和台账。

如果只是一次性 benchmark 或普通项目修改，本 Skill 不应自动触发；只有用户明确希望采用该协议时才使用。

实验型论文进一步读取 [research.md](research.md)。成熟存量工程先读取 [adoption.md](adoption.md)，不要直接套新项目目录。
