# 赛种裁剪表

四件套任何赛种**不裁**：笔记系统、合规红线、基线不可污染、防自欺。
验证流水线按评测形态替换；环境层按平台形态替换。

| 赛种 | 全保留 | 替换/调整 | 门槛示例 |
|---|---|---|---|
| 算法/数据（Kaggle、CCF 大数据） | 笔记系统、基线纪律、红线、防自欺 | L1 对照 → 固定 CV/随机种子；新增"线下线上一致性"检查与提交配额管理 | 线下 ≥ +X 且线上方向一致才继续 |
| 系统/性能优化 | 全套（原生赛种） | 无 | 快检 <10min；全量 ≥ +1.5% 且 > 2×方差 |
| 应用/黑客松 | 笔记系统、红线、交付管理 | 门槛制弱化为 feature freeze + 演示可复现；验证 → 冒烟 + 演示脚本 | 功能冻结日；演示一遍过 |
| 安全/CTF | 笔记系统（笔记 = writeup 素材）、红线 = 赛规 | 验证流水线 → 复现验证；基线 → 已拿 flag 清单 | 复现成功才算 solved |
| 机器人/嵌入式 | 笔记系统、参数快照、环境坑记录 | source → 代码+固件双轨；backups 增加参数/标定快照 | 赛前 N 次连续成功 |
| 科研/论文复现 | 全套 | "官方评测" → 固定 benchmark；提交 → 开源发布 | 复现误差 ≤ ε |

## 裁剪时问自己的三个问题

1. 这个赛种的"官方评测"对应什么？（决定 L2 全量验证怎么做）
2. "保底"对应什么？（可提交的最好版本 / 已拿分 / 已验证复现）
3. "门槛"的数字从哪来？（官方评分波动、交叉验证方差、演示稳定性）

## 降档使用（小比赛/短周期）

周期 < 1 周的小比赛：保留笔记系统（可合并为单文件分段记录）+ 红线 + 保底快照；门槛制简化为"过/不过"二值；验证流水线只留 L0 + L2。流程开销不得大于收益。
