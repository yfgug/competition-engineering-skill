# 存量工程接管协议

用于已有大量实验、历史目录、旧入口或多套基线的项目。目标是先建立可信导航，再渐进整理；不要为了“符合模板”破坏现有证据。

## 一、只读盘点

先运行：

```text
node <skill-dir>/scripts/audit_workspace.cjs <项目目录>
```

审计只报告问题，不移动或修改项目。结合人工检查确认：

- 真正的 Git 根和源码根是否相同。
- 当前推荐版本由哪个 commit、tree hash、快照或官方结果证明。
- 哪个文件是当前入口，是否还有多个互相冲突的入口。
- 工作树中的改动属于用户、历史实验还是未知来源。
- 运行脚本、原始结果、交付物和旧材料分别在哪里。
- 外部凭证、敏感 ZIP、日志和数据是否有传播风险。

审计警告是调查线索，不是自动删除或重构许可。

## 二、建立迁移映射

先写一张映射表，不立即搬目录：

| 现有位置 | 规范职责 | 当前权威性 | 动作 |
|---|---|---|---|
| <旧目录> | notes/results/source/... | current/historical/unknown | keep/link/migrate/archive |

同一职责出现多个目录时，例如 `output/` 与 `outputs/`：

1. 识别调用者、更新时间、内容和版本关系。
2. 选一个未来规范位置。
3. 先更新入口和新产物写入位置。
4. 保留旧位置的只读说明或兼容期。
5. 用户授权后再移动或归档。

不要通过目录名猜测“best”“backup”或“final”是否可信；必须检查 commit、状态、哈希和对应证据。

## 三、恢复唯一动态入口

创建或修复 `00_先看这里.md`，只保留：

- 当前目标和阶段。
- 指标契约或研究类型。
- 当前推荐的不可变身份。
- 最新权威笔记和原始证据。
- 当前工作树边界。
- 下一步唯一动作。

`AGENTS.md` 保存稳定约束，不复制几十篇动态笔记。历史索引放 `notes/README.md`。入口指向的路径必须存在，并优先使用项目相对路径。

## 四、处理绝对路径

成熟项目迁移后，文档中的 `D:\old-root\...`、`/home/old-user/...` 很容易失效。

- 项目内部文件改用相对路径。
- 远程机器、共享存储或容器路径保留环境前缀，例如 `cluster-a:/workspace/...`。
- 必须保留旧绝对路径作为历史证据时，同时写当前替代路径。
- 不对全部历史笔记做无差别替换；先修当前入口和活跃权威链。
- 修复编码损坏或路径拼写错误时留下更正记录。

## 五、整理持久化笔记

不要求旧笔记立即转换成新模板。按优先级处理：

1. 当前入口指向的活跃笔记。
2. 当前基线、关闭路线和外部提交证据。
3. 仍可能重开的实验。
4. 纯历史材料。

为旧笔记建立摘要索引，并在新笔记中使用 `supersedes`。大量历史笔记可以保持原格式，只要能定位、读取且不冒充当前权威。

## 六、拆分评测与提交

从长篇历史笔记提取最小台账：

- 本地运行和方差进入 `notes/_evaluations.md`。
- 官方评测、论文投稿和 artifact 发布进入 `notes/_submissions.md`。
- 有效失败路线进入 `notes/_closed_routes.md`。
- 原始日志和大文件仍留在原位置，台账只记录路径、哈希和摘要。

不要为了补齐台账重新消耗官方评测额度、额外投稿或重复昂贵实验。

## 七、迁移验证

迁移或整理后检查：

- 入口中的所有当前路径可解析。
- 当前推荐身份与原始证据一致。
- Git worktree、submodule 和外部仓库关系未被破坏。
- 脚本中的相对路径仍从声明的工作目录运行。
- UTF-8、BOM、NUL 和换行没有被意外改写。
- 用户改动、外部凭证和历史产物没有被误提交。
- 原有复现命令和交付包仍可用。

迁移笔记必须记录移动映射、哈希、未变清单和回滚方式。

## 八、停止条件

当以下条件成立时，先停止结构整理并回到实际研究或比赛：

- 唯一入口可靠。
- 当前基线和证据可以定位。
- 新实验有规范落点。
- 高风险重复目录已经标记清楚。
- 剩余问题只影响历史美观，不影响决策或复现。

工程治理的成本不应超过它防止的风险。
