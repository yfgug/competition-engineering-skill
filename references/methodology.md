# 方法论全文（通用版）

> 从实战提炼并做领域无关化。适用于"周期 ≥ 3 周 + 有评测/评分 + 以 AI 为主要执行者"的比赛。

## 一、七条核心原则

1. **聊天记忆不可靠，一切结论落盘。** AI 会话会断开、压缩、丢上下文。所有实验结论、坑、路线状态必须写进持久化笔记。笔记是唯一事实源，聊天只是工作现场。
2. **AI 是执行者，不是记忆者。** 每次新会话让 AI 先读入口文件和权威笔记链再动手，不指望它"记得上次"。
3. **单变量实验 + 事先量化门槛。** 一次只改一个变量；每条路线动手前先定好"继续/关闭"的数字门槛，不过门槛直接关闭。
4. **合规红线前置固化。** 开赛第一周把官方规则/Q&A 逐条翻译成红线清单写进约束文件，作为 AI 的 hard stop。执行纪律本身就是分数。
5. **保底不可污染。** 官方验证过的最优版本是不可变基线。实验一律从干净基线拉独立副本，失败即丢弃，永远不覆盖保底。
6. **诚实记录失败。** 每条被关闭的路线写清证据和"什么新证据才允许重开"，防止未来的自己和 AI 重复烧算力。
7. **防自欺。** 每次实验后明确写下"什么没有变"；识别并记录评测方差，小于方差的差异一律视为噪声。

## 二、目录结构

```text
<项目根>/
├── 00_先看这里.md        # 唯一入口：当前状态 + 权威指向 + 下一步
├── README.md             # 给人看的简介（不放易过期的状态）
├── AGENTS.md             # AI 约束与路由
├── notes/                # 持久化笔记 + README 索引 + 两条台账
│   ├── _closed_routes.md # closed 路线登记表（防重复烧算力）
│   └── _submissions.md   # 评测台账（commit/期望/实际出分/方差识别）
├── scripts/              # 全部脚本，命名自索引
├── results/              # 实验结果归档（每实验一子目录，含 summary）
├── backups/              # 基线快照：压缩包 + SHA256 + 记录
├── source/               # 比赛源码（git 管理，干净树纪律）
├── deliver/              # 交付物：同目录永远只有一个"当前推荐版"
├── archive/              # 已关闭方向、旧版本交付物的归档
└── tmp/                  # 临时文件，定期清空
```

根目录纪律：

- 根目录只放 `00_先看这里.md`、`README.md`、`AGENTS.md`，其余全是目录。
- 不允许 `新建 Markdown 文件.md`、`最终版_v2_最终最终.zip`、`output` 与 `outputs` 并存这类产物。
- 交付物出新正式版后旧版立刻入 `archive/`；每类东西只有一个规范位置。

## 三、持久化笔记系统

### 触发时机

任何**实质性事件**之后、切换方向之前：完整实验/官方出分/路线关闭/崩溃异常/提交交付/新坑/纠正旧结论。

### 命名

`notes/YYYYMMDD_NN_主题_状态.md`（日期前缀根治纯递增编号后期冲突的问题；状态 ∈ open / pending / closed）。

### 正文七要素

1. **背景与假设**：为什么做，预期收益来源。
2. **方法**：环境标识（作业号/容器/机器）、基线版本、精确到文件级的改动清单。
3. **结果**：原始数字直接贴（评分指标 + 过程指标 + 是否有输出漂移）。
4. **判定**：对照事先写下的门槛，过/不过；不过即 closed。
5. **未变清单**：明确列出"什么没有变"——防自欺关键段。
6. **坑**：过程中一切反直觉现象（尤其环境类：编码、路径、缓存、代理）。
7. **下一步**：只写一个推荐动作，防路线发散。

### 笔记间关系

- 新结论覆盖旧结论：新笔记头部写 `supersedes`，旧笔记不删不改（历史就是证据）。
- 索引只做路由不复述正文；每篇笔记一个主题；组合实验单独开篇引用成员。

### 两条台账（系统的防呆层）

- **`_closed_routes.md`**：每条 closed 路线一行（主题 / 一句话证据 / 重试条件）。AI 开新路线前先查此表，命中"已关闭且重试条件未满足"直接拒绝执行。
- **`_submissions.md`**：每次官方提交一行（日期 / commit / 期望 / 实际出分 / 差值）。同一版本重复提交的差值就是评测方差的实测记录。

## 四、验证流水线（金字塔 + 门槛制）

```text
L0 快检冒烟    → 只判"能不能继续"：跑通？崩溃？输出异常？（不看分数）
L1 对照实验    → 同环境 A/B（或 A-B-A 消环境方差）
L2 全量验证    → 完整评测集 + 完整指标 + 有效性双保险
L3 门槛判定    → 对照事先定好的数字门槛（含方差余量）
L4 提交决策    → 与保底对比；可回滚；用户授权后提交
```

- 门槛事先写（写在路线的 open 笔记里）。
- 方差标定：早期同一版本重复评测 2–3 次，波动范围记入笔记；此后小于波动的差异一律视为噪声。
- 有效性双保险：性能/分数指标 + 正确性/质量指标永远一起看。
- 提交配额管理：每次提交前过 L4；提交后记录 commit、期望、实际出分。

## 五、基线与实验管理

1. **基线三件套**：新官方验证版本 → tag + 源码压缩包 + SHA256 + 笔记（分支/commit/成绩/日期）。
2. **实验隔离**：每方向独立分支/副本；失败直接丢弃，不在失败品上缝补。
3. **干净树审计**：动手前 `git status --short` 必须为空；打包/导出前**再查一次**。
4. **导出纪律**：对外导出源码永远从 `git archive HEAD`（或干净 tag）导出，**绝不复制工作树**——工作树脏是反复出现的事故源。
5. **分支命名**：`exp/<主题>-<日期>`；候选 `candidate/<主题>-<日期>`。
6. **用词规则**：只有官方验证过的才叫 best；本地实验一律 candidate；禁用"稳定版"等歧义词。
7. **外部材料安全**：组委会/队友提供的 ZIP/源码，入库前先扫凭证（`.git/config` 里的 token、密钥文件）；发现即记录、隔离，绝不原样二次分享。

## 六、路线生命周期（状态机）

```text
open       定门槛、做单变量实验、L0/L1
  ↓ 门槛过
pending    L2 全量 + 有效性双保险
  ↓ 过线
candidate  用户授权 → 官方提交（记入评测台账）
  ↓ 出分
promoted   高于保底 → 晋升为新保底（走第五节基线三件套 + 更新入口）
closed     任意阶段不过线/出分不高于保底 → 关闭，登记 _closed_routes.md，写重试条件
```

**晋升检查清单**（官方出分确认高于保底后，一次性做完）：

```text
□ git tag + git archive 导出 zip + SHA256 → backups/
□ promotion 笔记（commit/成绩/与旧保底的对比数字），supersede 旧 best 笔记
□ 00_先看这里.md 更新"当前最优版本"与"最新权威笔记"
□ notes/README.md 权威路由置顶新笔记
□ _submissions.md 追加一行
□ 后续实验一律从新保底拉分支
```

**组合审计纪律**：多个单变量改动各自有效后，组合必须重新走 L1–L3 单独验证（收益不叠加是常态）；组合前的成员版本与组合版本都要在评测台账留档。

## 七、AI 会话协议

- 开始仪式：读记忆 → 读入口 → 按权威路由读笔记 → 复述状态与边界 → 动手。
- 结束仪式：写笔记 → 更新入口与索引 → 留下一步唯一动作。
- 一场会话只推进一个方向；不混改、不同时开两条路线。
- 分工：AI 做读码/补丁/跑脚本/写笔记/审计；人做授权、看方向、定门槛。AI 不越权做有外部后果的动作。

## 八、脚本与产物命名

`<动词>_<对象>_<变体>_<日期>[_<环境标识>]`；动词固定语义：run/launch/poll/probe/inspect/check/setup/build/start/archive/analyze。结果归档 `results/<主题>_<日期>/summary.md`。

## 九、环境与平台层（有远程算力时）

- 容器/机器生命周期脚本化；凭证只从本地配置读，永不入笔记/日志/产物。
- 冷启动加速（缓存编译产物）；快启结果只用于方向筛选，正式结论必须官方路径全量复跑。
- 环境坑集中一篇"环境坑大全"笔记，AGENTS.md 指向它。
- 关键现场准备"只填空、只敲现成命令"的执行卡。

## 十、交付物管理

- 单一 ZIP + SHA256 + 文件清单 manifest + 独立解压校验（换目录解一遍核对逐文件哈希）。
- 交付前审计：无凭证泄漏、无脏文件、版本与笔记一致、一条命令可复现。
- `deliver/` 只留当前推荐版；旧版进 `archive/` 并在笔记记 SHA256。

## 十一、冷启动清单（Day 1–2）

```text
□ 建目录骨架（scaffold 脚本，含两条台账模板）
□ 通读官方规则/Q&A → 写 AGENTS.md 红线（逐条可执行）
□ 建 notes/ 模板 + README 索引 + 第一篇 open 笔记（定第一轮门槛）
□ 跑通 baseline → tag + zip + SHA256 进 backups/ + 笔记
□ 写 L0 冒烟脚本与 L2 全量脚本（run_ 命名）
□ 方差标定：同一 baseline 评 2–3 次，记入 _submissions.md
□ 平台层：容器生命周期脚本 + 冷启动缓存方案
□ 外部材料安全扫描（组委会包/共享代码）
□ 00_先看这里.md 写第一版
```

常态循环：读权威 → 单变量实验 → 快检 → 对照 → 全量 → 门槛判定 → 写笔记 → 更新索引 → 下一条路线。
