# 方法论全文

> 面向持续多轮、存在明确评测、需要人和 AI 跨会话协作的竞赛工程与实验型论文研究。流程强度应与周期、提交额度、算力成本、结论风险和复现要求相匹配。

## 一、证据与权威

按以下顺序解决冲突：

1. 官方规则、Q&A、官方评测结果，或研究中的原始数据、实验协议和一手来源。
2. 不可变原始日志、评测产物、输入数据版本和哈希。
3. Git commit、tag、diff、构建配置和环境锁定文件。
4. 实验笔记与索引。
5. 聊天中的回忆或口述结论。

笔记负责解释“做了什么、为什么这样判断、证据在哪里”，不是原始证据的替代品。无法核验的陈述写入笔记时标记为 `unverified`，之后用日志、代码版本或官方结果关闭验证缺口。

## 二、文件职责

```text
<项目根>/
|-- 00_先看这里.md         # 唯一动态入口：目标、指标契约、当前推荐、权威证据、下一步
|-- README.md              # 面向人的稳定说明，不保存易过期状态
|-- AGENTS.md              # 稳定红线、工作纪律、环境入口
|-- notes/
|   |-- README.md          # 历史索引
|   |-- _evaluations.md    # 本地/离线评测与噪声记录
|   |-- _submissions.md    # 外部提交台账
|   `-- _closed_routes.md # 已拒绝路线与重试条件
|-- scripts/               # 可重复执行的脚本
|-- results/               # 原始评测产物及 summary
|-- backups/               # 必要的离线灾备快照
|-- source/                # 项目源码
|-- deliver/               # 当前待交付物
|-- archive/               # 历史交付和停止维护的材料
|-- paper/                 # 研究 profile：claim、图表与论文状态
|-- data/                  # 研究 profile：数据/模型来源、许可与处理链
`-- tmp/                   # 可删除临时文件
```

避免维护多份“当前权威”：

- `00_先看这里.md` 是当前状态和权威证据的唯一入口。
- `AGENTS.md` 只写稳定规则，不复制动态笔记列表。
- `notes/README.md` 只做历史索引，不复述当前状态。
- 原始结果放 `results/`，笔记只引用路径和摘要数字。
- 项目内部引用优先使用相对路径；机器、容器或集群路径写明环境标识和替代入口。

存量项目不要求立即改成上述目录。先按 [adoption.md](adoption.md) 做只读盘点和职责映射，保证当前入口、基线与证据可信后再渐进迁移。

## 三、版本控制预检

开始新实验时记录边界，而不是要求整个项目永远无修改：

1. Git 项目记录 `base_commit`、当前分支和初始 `git status --short`。
2. 初始改动来源不明且与目标文件重叠时停止，请用户确认。
3. 与实验无关的用户改动保留并绕开，不回滚、不提交。
4. 本次实验产生的已知脏文件属于正常工作状态；在笔记中记录范围。
5. 非 Git 项目记录输入文件清单、大小和 SHA256，或在用户同意后初始化 Git。

完成实验和导出前再次审计 diff，确认没有混入初始无关改动。对外源码优先从明确 commit 或内容哈希对应的快照导出，不从无法解释的工作树打包。

## 四、工作类型

### 因果或性能实验

目标是判断某个变量是否产生收益。优先单变量、同环境对照和预先门槛。多个已验证变量组合后必须作为新候选重新评测。

### 修复、集成和基础设施工作

允许一组完整且必要的改动，例如跨文件 bug 修复、构建系统迁移或不可拆分的接口更新。记录改动范围、验证命令和未涉及区域，不为形式上的“单变量”拆坏原子性。

## 五、路线生命周期

```text
proposed
   |
running
   |-- pass ------------> candidate --(满足晋升规则)--> promoted
   |-- valid failure ---> rejected
   |-- evidence weak ---> inconclusive
   `-- evaluation bad --> invalid --(修复评测条件)--> running
```

- `rejected`：评测有效且未过门槛，登记 `_closed_routes.md` 和重试条件。
- `inconclusive`：样本、运行次数或证据不足，不得伪装成成功或失败。
- `invalid`：环境、数据、命令或指标计算有问题，先修评测条件。
- `candidate`：本地验证通过但尚未满足全部晋升条件。
- `promoted`：成为新的推荐基线。

文件名状态 `open | pending | closed` 表示笔记是否还需要推进；实验结果单独使用 `pending | pass | fail | inconclusive | invalid`，不要混为同一个枚举。

## 六、验证流水线

```text
L0 冒烟与正确性 -> 能否继续评测
L1 同环境对照   -> 基线与候选的可比结果
L2 代表性/全量  -> 足够覆盖正式场景
L3 决策门槛     -> 指标方向 + 硬约束 + 噪声余量 + 实际收益
L4 外部提交     -> 仅在官方评测、投稿或发布需要且用户授权后执行
```

具体指标契约、重复次数、方差和晋升计算见 [evaluation.md](evaluation.md)。重复官方提交不是默认的方差估计手段；优先使用本地固定数据、配对运行、多随机种子或重采样。

## 七、持久化笔记

### 触发时机

完整实验、官方出分、论文 claim 状态变化、路线状态变化、评测失效、崩溃异常、提交交付、新发现或旧结论更正后写笔记。探索过程不要求每一步都落盘；形成可复用结论或状态变化时再写。

### 命名

`notes/YYYYMMDD_NN_主题_状态.md`，状态为 `open | pending | closed`。

### 内容

使用 `assets/scaffold/notes/_TEMPLATE.md`。至少记录：

- 假设、工作类型和预先门槛。
- 基线、初始工作树、环境和精确改动范围。
- 评测命令、原始产物路径和关键指标。
- 结果分类及其证据。
- 未变清单和下一步唯一动作。

历史笔记默认追加更正并用 `supersedes` 建立关系。发现凭证、个人信息或会造成危险执行的错误时，可以审计后修订或删除敏感内容，并留下更正说明；“历史不可改”不能凌驾于安全和事实纠正。

## 八、基线与晋升

基线使用 commit SHA 或内容哈希作为不可变身份。tag 是易读别名，压缩包和 SHA256 是灾备或交付层，不强制每次实验都创建。

候选晋升必须同时满足：

1. 主指标按声明方向超过基线，并越过噪声余量和最小实际收益。
2. 正确性、资源、稳定性和赛规等硬约束全部通过。
3. 结果可由记录的命令、环境和原始产物复现。
4. 需要官方验证时，已获得授权且官方结果满足规则。
5. 多目标场景符合预先声明的优先级或 Pareto 决策，不以单个分数机械决定。

论文项目还要满足 [research.md](research.md) 的 claim-evidence、反选择性报告、图表追踪和适用范围要求。竞赛成绩可以成为论文证据，但不自动证明跨环境的普遍结论。

晋升后更新 `00_先看这里.md`、promotion 笔记和相关台账。后续实验从新基线开始；旧基线保留为可定位的 commit 或哈希，不依赖可移动分支名。

## 九、AI 会话协议

开始：

1. 读 `00_先看这里.md`。
2. 读 `AGENTS.md`。
3. 只读取入口指向的必要笔记、评测和原始证据。
4. 复述当前目标、指标方向、基线、工作树边界和本次动作。

结束：

1. 为实质事件写笔记或更正。
2. 更新评测、外部提交或关闭路线台账。
3. 更新 `00_先看这里.md` 的当前推荐、权威证据和下一步。
4. 保留用户无关改动，不擅自 commit、push、提交或交付。

## 十、交付管理

- 从明确 commit 或内容哈希对应的快照构建。
- 生成 manifest 和整体/逐文件哈希，独立目录解压或部署验证。
- 使用允许清单确定交付内容，扫描凭证、私钥、环境文件和个人信息。
- notebook、必要日志和评测证据按赛制与复现需要决定，不按扩展名一刀切删除。
- `deliver/` 保存当前待交付物；历史版本可归档，但移动或删除前遵守用户授权和仓库规则。
- 论文交付验证 claim 矩阵、核心图表重建、引用、数据许可、伦理和匿名化。

## 十一、冷启动清单

```text
[ ] 用 scaffold --dry-run 预览，再创建目录
[ ] 读取规则/Q&A，填写 AGENTS.md 稳定红线
[ ] 在 00_先看这里.md 填指标方向、约束、评测命令和晋升规则
[ ] 建立 Git 基线或文件哈希快照
[ ] 跑通 L0 和基线评测，原始结果进入 results/
[ ] 本地噪声与重复评测进入 _evaluations.md
[ ] 外部提交只进入 _submissions.md，并记录配额或截止时间影响
[ ] 写第一篇 open 笔记和下一步唯一动作
```

研究项目另外执行：

```text
[ ] 使用 --profile research 创建 paper/ 与 data/ 模板
[ ] 声明 reproduction/exploratory/confirmatory/competition-to-paper
[ ] 建立 claim-evidence 矩阵
[ ] 建立数据与模型来源、许可和处理链
[ ] 为核心图表登记生成脚本、输入和哈希
```
